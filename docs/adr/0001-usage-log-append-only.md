# 0001. 用量流水表不设外键、只增不改

日期：2026-09-11

## 状态

已接受

## 背景

用量统计需要一个记录每次模型调用消耗的地方。仓库里其它表都用外键把记录挂在
用户、会话、智能体上，并广泛使用 `ON DELETE CASCADE` / `ON DELETE SET NULL`。

但用量流水是**账单**：它的职责是回答「过去发生了什么」，而不是「现在有什么」。
如果沿用外键，会出现两个问题：

- 删除一个会话，它名下的用量记录会被级联删掉，总消费凭空变小；
- 删除或改名一个智能体，历史归属变成 NULL，报表里那一行失去意义，或者直接消失。

## 决策

用量流水表**不设任何外键**，并且只增不改。
智能体 id、用户 id、会话 id 都按普通整数列存储，同时在写入时冗余一份智能体名称快照。

报表按「id + 名称快照」聚合，因此智能体改名后历史仍归到同一行，
智能体被删除后历史仍然可读，并显示当时的名称。

## 后果

- 账单不会因为删数据而失真，这是这套统计能被信任的前提。
- 代价是失去数据库层面的引用完整性：id 可能指向一个已不存在的对象。
  这是可接受的 —— 流水本来就不需要能 join 回业务表，它自带展示所需的全部信息。
- 后续如果要按用户或模型维度做报表，沿用同样的做法：存 id，再冗余一份展示名。

## 备选方案

- **使用外键 + `ON DELETE SET NULL`**：历史归属会在删除时丢失，报表出现无法解释的
  「未归属」空洞，账单不再完整。
- **使用外键 + `ON DELETE CASCADE`**：删会话即删账，直接违背统计的目的。
- **使用外键 + 禁止删除业务数据**：把账单的完整性建立在「业务数据永不删除」上，
  约束过强，且现有代码已有大量删除路径。
